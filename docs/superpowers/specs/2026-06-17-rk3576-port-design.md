# RK3576 鲁班猫移植设计 — iflyVoice 语音代理

**状态**：Draft（待用户复核）
**日期**：2026-06-17
**分支**：`rk3576_lubancat`
**目标平台**：Rockchip RK3576 鲁班猫，Ubuntu 22.04.5 LTS (GNU/Linux 6.1.99-rk3576 aarch64)

---

## 1. 背景与目标

### 1.1 项目现状
iflyVoice 是 Windows 桌面悬浮球语音 AI 助手，融合 ASR / LLM / TTS / 显示器 DDC-CI 控制 / 桌面应用管理 / B 站搜索。当前版本（commit `4222af8`）依赖大量 Windows 专有 API（Win32 ctypes、pycaw、PowerShell、WMI、nircmd.exe），无法直接在 ARM Linux 嵌入式平台运行。

### 1.2 移植目标
将 iflyVoice 改造为运行在 RK3576 鲁班猫上的**语音 AI 代理**，最终用途为：
- 板子搭载 Ubuntu 22.04.5 LTS（aarch64）
- 通过外接 HDMI 显示器呈现悬浮球 UI
- 麦克风采集 + 6 TOPS NPU 跑 ASR / 唤醒词
- **通过局域网控制远端 Windows PC**（PC 端的 DDC-CI 显示器、桌面应用、B 站搜索等操作由 PC agent 接管）

### 1.3 设计原则
1. **瘦客户端定位**：RK3576 是语音前端，PC 才是执行者。所有 PC 侧操作不重写到板子
2. **Executor 抽象**：业务层（widget / voice_pipeline）只调接口，不知道也不关心执行后端是 local 还是 remote
3. **降级优先**：每层失败必须有降级路径，语音链路不卡死
4. **ARM 验证门禁**：所有改动必须在板子上跑过 bench / e2e / 长稳 三套测试

### 1.4 范围与非范围

**范围内**（本期实现）：
- RK3576 端：widget.py / voice_pipeline.py / server.py 移植
- executor 抽象层 + pc_agent 客户端 + dev_stub
- NPU 跑 ASR（SenseVoice-Small on RKNN）+ 唤醒词
- 本机屏软调（backlight / xrandr）
- 远端 Win PC agent 的 **HTTP 接口契约**（实现放下一期）

**范围外**（本期不实现，下期再做）：
- Win PC agent.exe 端代码（接口先定，实现后续）
- 多 PC 代理 / 路由器级联
- 移动端 App
- 产品化打包 / 商店分发
- LLM 本地化（Ollama 仍走远端 `192.168.1.32:11434`）

### 2.2 职责切分

| 组件 | 位置 | 职责 |
|------|------|------|
| 语音采集 / VAD / 唤醒 | RK3576 | 麦克风 → Silero VAD → 唤醒词检测 |
| ASR | RK3576 NPU | SenseVoice-Small（RKNN），替换远端 SenseVoice |
| LLM 意图识别 + 对话 | 远端 Ollama | `192.168.1.32:11434`，RK3576 只代理 |
| TTS | RK3576 | edge-tts 流式 + 扬声器 |
| UI / 悬浮球 | RK3576 | 外接 HDMI 屏 |
| 显示器 DDC-CI | **Win PC agent** | RK3576 不实现 |
| 桌面应用管理 | **Win PC agent** | RK3576 不实现 |
| B 站搜索代理 | **Win PC agent** | RK3576 不实现 |
| 本地屏软调（xrandr/backlight） | RK3576 | 调自己的 HDMI |

### 2.3 关键决策

- **NPU 跑 ASR**（SenseVoice-Small on RKNN），替换远端 SenseVoice
- **NPU 跑唤醒词**（自训或 openWakeWord 转 RKNN）
- **Ollama 走远端**（NPU 不跑 LLM）
- **Win PC agent 用 HTTP REST + JSON**（简单、调试方便；WebSocket 仅在长连接需求出现时升级）
- **`dev_stub` 只在无 PC 时用**（开发自测、单测），不是用户可用功能
- RK3576 上**不实现** DDC-CI、桌面应用管理、B 站代理的本地版

**NPU 术语说明**：
- **NPU**：RK3576 内置的神经网络处理单元，6 TOPS @ INT8
- **RKNN**：Rockchip NPU 的官方推理 SDK / 工具链（`rknn-toolkit2-lite2` 是板子侧推理运行时）
- 模型需先在 x86 PC 上用 `rknn-toolkit2` 转换（ONNX/PyTorch → RKNN 格式），再部署到板子

## 6. 错误处理

**核心原则**：每层失败都要有"降级路径"，不卡死语音链路。

| 失败点 | 现象 | 降级策略 | 用户感知 |
|--------|------|----------|----------|
| 麦克风掉线 | 采集 read 异常 | 自动重连 3 次；超过 30s 提示 | UI 弹提示 + TTS 播报 |
| Silero VAD 模型加载失败 | 启动报错 | 退回"能量阈值"简单 VAD（裸 RMS） | 唤醒灵敏度变差但能用 |
| NPU ASR 加载失败 | rknn 导入/模型不存在 | 自动切到远端 SenseVoice；远端不通回退到 Ollama 直输文字 | UI 状态栏显示"ASR: 远端" |
| NPU 推理超时（>5s） | 推理卡住 | 杀进程重试 1 次；再次失败切远端 | 偶尔卡一下，正常 |
| 唤醒词误触发 | 杂音唤醒 | VAD 阈值动态上调（每 5 分钟统计假阳率）+ 唤醒后必须听到语音才进入识别 | 唤醒变严，假阳率降低 |
| Ollama 超时/不可达 | LLM 调用失败 | 回退到普通文本回复 | 短回应 |
| Ollama 意图解析失败 | JSON 解析报错 | 当作普通对话，不调 executor | 走闲聊分支 |
| Win PC agent 不可达 | HTTP 超时 3s / 5xx | TTS 播报"PC 没连上，请检查网络"；连续失败 3 次后状态栏显示断线 | 不影响语音/UI |
| Win PC agent 执行失败 | 返回 `{ok: false, err}` | err 字段直接转 TTS 播报 | 用户听到具体错误 |
| 显示器 DDC-CI 失败 | agent 报"显示器不支持" | 改走本地 xrandr / sysfs 软调 | 自动透明降级 |
| TTS edge-tts 失败 | 网络问题 | 静默，不朗读（仅文字回显） | 用户看不到提示但能读屏 |
| 扬声器占用 | ffplay 启动失败 | 杀残留 ffplay 进程，重试 1 次 | 偶尔没声 |
| 桌面服务崩溃 | Qt 死锁 | systemd 监控 + 自动重启 + 写崩溃日志 | 透明 |
| RKNN runtime 缺失 | 板子没装 rknn | 启动检查 → 关 npu_asr → 切远端 | 启动时一行警告日志 |

**关键实现**：
- `executor.pc_agent` 内部包 `tenacity` 重试：3 次指数退避（1s/2s/4s）
- `voice_pipeline` 持有"上一次的可用 executor"标记，agent 连续失败时**不每句都试**，改成心跳探测（每 30s ping 一次）
- 所有失败写 `widget.log`（已有），带时间戳和上下文
- PySide6 线程用 `QThread`，长操作（HTTP/NPU 推理）都丢到子线程，**绝不**阻塞 UI 线程

### 7.7 依赖与运行时兼容（一次性检查）

| 依赖 | 检查方法 | 失败影响 |
|------|----------|----------|
| `onnxruntime` aarch64 wheel | `pip show onnxruntime` | VAD 不能用 |
| `PySide6` aarch64 wheel | `pip show PySide6` + 启动空窗口 | UI 崩溃 |
| `rknn-toolkit2-lite2` 是否存在 | 尝试 `import rknn` | ASR 切远端 |
| `pulseaudio` 守护进程 | `pactl info` | 音量控制失效 |
| `/dev/snd` 权限 | `ls -l /dev/snd` | mic/speaker 不可用 |
| `/dev/dri` 权限（Wayland 渲染） | `ls -l /dev/dri` | Qt 渲染降级到 sw |
| `/dev/i2c-*` 存在 | `ls /dev/i2c-*` | 仅影响本地屏 I2C 背光 |
| `ffmpeg` / `ffplay` | `which ffmpeg ffplay` | TTS 播放失败 |
| 中文/Unicode 字体 | `fc-list :lang=zh` | UI 中文方块 |
| 显示器 EDID 读取 | `edid-decode` | DDC-CI fallback |

**预检脚本**：`scripts/check_arm64.sh`，启动 widget 前跑一遍，不通过直接拒绝启动并打印缺啥。

### 7.10 CI 与发布门禁

- **PR 级 CI**（x86 runner）：跑单元 + 集成，**禁止**在没有 ARM 验证报告的情况下合并
- **板子 release 前必须跑**：`scripts/check_arm64.sh` + `tests/bench_arm64.py` + `tests/e2e_latency.sh` + 30min 长跑
- **性能回归**：`bench_report.json` 提交到仓库，每次跑对比上版本，超 20% 报警
- **崩溃日志兜底**：widget 死掉时 `widget.log` 自动 dump 栈，crash 报告归档到 `logs/crash/`
